# ยอดเข้าชม

หน้าแรก (`/`) และหน้าคาดการณ์ (`/ge-2026/prediction`) แสดงยอดเข้าชมแยกกันที่ท้ายหน้า เริ่มนับหลังเปิดใช้ฟีเจอร์ โดยนับทุกครั้งที่เปิดหน้าหรือรีเฟรช ไม่ใช่จำนวนผู้ใช้ที่ไม่ซ้ำ และไม่เก็บ IP หรือข้อมูลส่วนบุคคล

เบราว์เซอร์ส่ง `POST /api/page-views?page=home` หรือ `page=prediction` เมื่อหน้าแสดงผล จึงไม่นับการ build หรือ prefetch ของ Next.js หากบันทึกไม่สำเร็จจะแสดง `—` และยังใช้งานหน้าเว็บได้ตามปกติ

ใช้ที่เก็บข้อมูลตามลำดับเดียวกับผลคาดการณ์:

1. PostgreSQL / Neon ผ่าน `DATABASE_URL` หรือ `POSTGRES_URL` สร้างตาราง `page_views` อัตโนมัติในการใช้งานครั้งแรก บัญชีฐานข้อมูลต้องมีสิทธิ์สร้างตาราง การเพิ่มยอดเป็น atomic upsert
2. Redis / Vercel KV ผ่าน `KV_REST_API_URL` และ `KV_REST_API_TOKEN` ใช้คำสั่ง `INCR` กับ key `page-views:v1:home` และ `page-views:v1:prediction`
3. ในเครื่องที่ไม่มีฐานข้อมูล เก็บใน `data/page-views.json` ซึ่งไม่ commit โดยรองรับหลายคำขอพร้อมกันใน process เดียว บน Vercel ต้องตั้งค่าฐานข้อมูล

ยอดไม่ย้ายอัตโนมัติหากเปลี่ยนที่เก็บข้อมูล ตัวนับนี้เป็นยอดเข้าชมทั่วไป ไม่ได้ป้องกันการเพิ่มยอดด้วยการเรียก API ซ้ำ
